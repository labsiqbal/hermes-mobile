# HM-PROD-01 — Management transport and UI contract

## Delivery boundary

This lane adds `Manage.tsx`, its own `manage.css`, the narrow `management-client.ts` adapter, and deterministic `check-management.mjs`. Manage exports a default component with exactly `{ conn: SavedConnection, client: HermesConnection, onSettings: () => void, onBots: () => void, onWorkspace: () => void }`; connection types come from the existing `lib/hermes-client`.

The component is content for the shared Header/body/TabBar. It adds no app shell, global theme, connection singleton, login mechanism, router, dependency or native bridge. Gateway/connection settings, Bots and workspace navigation delegate to those callbacks. The independent shell integration must import it; the original worktree App is intentionally untouched.

**Implemented UI is not complete Desktop action parity.** The earlier inventory is a source-audit input, not a completion certificate. No claim is made that its 229 actions are complete. This release implements the read surfaces below and one explicitly confirmed, read-back-verified profile-description mutation. All remaining actions remain unimplemented even where the upstream has a handler.

Canonical gate: `backlog.md`, HM-PROD-01 in the canonical repository. Visual reference: reviewed A, `parity-review/design/parity-shell/index.html` (read-only). Selection is local to Manage and intentionally does not change session identity, profile defaults or an active gateway.

## Authentication, compatibility and failure discipline

- WebSocket calls reuse the existing authenticated `HermesConnection`; no second socket or login is introduced. Credentials never appear in URLs, logs, error messages or page content.
- REST requests use the exact connected gateway base and existing browser session cookies (`credentials:'include'`), `GET`, `Accept: application/json`, `cache:'no-store'`, `redirect:'error'`. No private client fields are inspected, and credentials are never copied from saved settings. Bearer-only/nonbrowser private authentication is not extracted; unavailable cookie-auth reads show reconnect guidance rather than falling back to another transport.
- **Actual proxy constraint:** unauthenticated read-only probes returned `404 text/plain` at `https://nuc.tailcf7779.ts.net:8451/openapi.json` and `401 application/json` at `/api/openapi.json`. A 401 behind middleware does not establish that an endpoint exists. Pinned source declares FastAPI's normal schema route, not an `/api/openapi.json` alternative. The shipped adapter never probes either schema URL and changes no route/service. Tests emulate static root plus `/api` proxy rather than a fictional working root schema.
- **No-echo REST scope:** memory and messaging lack a profile owner echo. To work safely without schema discovery or assuming that an older server honors `?profile`, require `/api/profiles/active.current === selectedProfile` before and after reading. `active` is never accepted as process identity. Other selected profiles fail closed before fetching their memory/platform data. Cron remains usable across profiles because each row must echo ownership. An old response without owner echoes is rejected (empty responses remain empty). This is a conservative compatibility restriction, not a claim that upstream cannot address named profiles.
- Scope strings are preserved literally; whitespace, uppercase, empty names, path-like names and `all/current/custom` aliases are rejected. Profile detail responses must echo the requested name. Kanban scope is separate: gateway + explicit board, not an implicit profile fallback.
- Every request has a 15-second bound. HTTP reads additionally abort fetch and body readers. JSON media type is required; streamed decoded bytes are capped at **2 MiB**, including responses without `Content-Length`. Invalid JSON/HTML/oversized bodies are structured errors, not raw body dumps. There is no request retry loop or automatic mutation retry.
- RPC cancellation cannot recall bytes already transmitted. It suppresses late UI results; the existing client's pending-call timeout still owns socket cleanup. A signal aborted before the dispatch microtask prevents the RPC entirely. UI loaders are keyed to manager/profile/board and abort on unmount; previous-scope data cannot paint under a new identity.
- Reviews are immutable one-use objects owned by the adapter instance. A forged review, missing confirmation, wrong selected profile, reused review or preflight conflict cannot invoke configure. A null/malformed acknowledgment **after** dispatch is `outcome:'unknown'`, never “No state changed.” An acknowledged write with failed/mismatched readback likewise remains unknown. 401/403, unsupported method, missing endpoint/profile and read failures explicitly state no state changed; server-provided errors are not echoed.
- Nothing in this module runs while the phone is closed; no background-worker or delivery guarantees are introduced.
